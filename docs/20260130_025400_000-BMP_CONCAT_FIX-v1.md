# BMP Multi-Image Concatenation Bug - Complete Fix Documentation

**Document Version:** 1.0  
**Date:** 2026-01-30  
**Issue:** Video generation failed with multiple BMP images - only generated 67 frames instead of 331 frames  
**Status:** ✅ RESOLVED

---

## Executive Summary

Videos with multiple background images (BMP format) were generating incorrectly - producing only 2.23 seconds of video instead of the expected 11 seconds, with audio only present in the last 2 seconds and most subtitles missing. The root cause was FFmpeg's `concat` demuxer failing to respect duration specifications for static BMP images. The solution implemented was a two-stage conversion process: first converting each BMP to an individual video segment, then concatenating those video segments.

---

### Root Cause Identification

**FFmpeg's `concat` demuxer behavior with static images (BMP):**

The concat demuxer reads image files frame-by-frame. For static image formats like BMP:

- Each BMP file contains exactly **1 frame**
- The `duration` directive tells concat how long to "display" that frame
- However, concat doesn't **generate** frames to fill that duration
- It simply takes the 1 frame from each BMP and marks its display time
- When piped to video filters, only those original frames are available

**Behavior breakdown:**

```
BMP 1 (1 frame) → duration 2.208s → Still only 1 frame in stream
BMP 2 (1 frame) → duration 2.208s → Still only 1 frame in stream
BMP 3 (1 frame) → duration 2.208s → Still only 1 frame in stream
BMP 4 (1 frame) → duration 2.208s → Still only 1 frame in stream
BMP 5 (1 frame) → duration 2.208s → Still only 1 frame in stream
Last BMP (1 frame, no duration)

Total frames in stream: 6 frames (not 6 × 66 frames as expected)
```

The `fps` filter then tries to convert this to 30fps, but with only 6 unique frames over 11 seconds, it can only spread those 6 frames across 67 output frames.

## Solution Design

### Approach Evaluation

#### ❌ Rejected Approaches

1. **Adding `-r 30` to input options**
   - Doesn't solve the fundamental issue - concat still provides only 1 frame per image
2. **Using `-stream_loop` per image**
   - Extremely complex to implement dynamically with varying durations
3. **Using `filter_complex` with multiple loop inputs**
   - Manual testing failed: `Conversion failed` error
   - Too complex for dynamic image counts

#### ✅ Selected Approach: Two-Stage Conversion

**Strategy:**

1. **Stage 1:** Convert each BMP to an individual MP4 video segment with proper duration
2. **Stage 2:** Concatenate the video segments (which works correctly since they're already videos)

**Advantages:**

- Each segment is a proper video with correct frame count (2.208s × 30fps = 66 frames)
- Concat demuxer works perfectly with video files
- Clean separation of concerns
- Easy to debug individual segments

## Implementation Details

### Code Changes

#### File: `src/main/services/videoService.ts`

**Location:** Method `createVideo` (lines 69-262)

**Complete Rewrite:** The entire method was replaced with a two-stage implementation.

##### Stage 1: BMP to Video Segment Conversion

```typescript
const tempDir = path.join(path.dirname(outputPath), "temp_segments");
if (!fs.existsSync(tempDir)) {
  fs.mkdirSync(tempDir, { recursive: true });
}

const videoSegments: string[] = [];

for (let i = 0; i < images.length; i++) {
  const img = images[i];
  const imgDuration = hasCustomDurations
    ? imageDurations![i]
    : durationPerImage;

  const segmentPath = path.join(
    tempDir,
    `segment_${i.toString().padStart(3, "0")}.mp4`,
  );

  await new Promise<void>((resolveSegment, rejectSegment) => {
    logger.log(
      `[createVideo] Creating segment ${i + 1}/${images.length}: ${imgDuration}s`,
    );

    ffmpeg(img)
      .inputOptions(["-loop", "1", "-framerate", "30"])
      .videoFilters([
        `scale=${w}:${h}:force_original_aspect_ratio=increase,crop=${w}:${h}`,
        "format=yuv420p",
      ])
      .outputOptions([
        "-c:v",
        "libx264",
        "-preset",
        "ultrafast",
        "-crf",
        "28",
        "-t",
        `${imgDuration}`,
        "-pix_fmt",
        "yuv420p",
      ])
      .output(segmentPath)
      .on("end", () => {
        videoSegments.push(segmentPath);
        resolveSegment();
      })
      .on("error", (err) => {
        logger.error(`[createVideo] Segment ${i} error: ${err.message}`);
        rejectSegment(err);
      })
      .run();
  });
}
```

**Key Elements:**

- `-loop 1`: Loop the single-frame BMP image
- `-framerate 30`: Generate 30 frames per second
- `-t ${imgDuration}`: Exact duration for this segment
- Segments saved as `segment_000.mp4`, `segment_001.mp4`, etc.

##### Stage 2: Video Segment Concatenation

```typescript
const inputListPath = path.join(path.dirname(outputPath), "segments_list.txt");
const inputListContent = videoSegments
  .map((seg) => `file '${seg.replace(/\\/g, "/")}'`)
  .join("\n");

fs.writeFileSync(inputListPath, inputListContent);

let command = ffmpeg();

command = command
  .input(inputListPath)
  .inputOptions(["-f", "concat", "-safe", "0"]);

if (audioPath && fs.existsSync(audioPath)) {
  command = command.input(audioPath);
  command.outputOptions(["-map", "0:v", "-map", "1:a"]);
  command.outputOptions(["-c:a", "aac", "-b:a", "128k", "-ac", "2"]);
}

// Copy video since segments are already encoded
command = command
  .outputOptions(["-c:v", "copy", "-movflags", "+faststart"])
  .output(normOutputPath);
```

**Key Elements:**

- Concat list now contains video files, not BMP images
- `-c:v copy`: Copy video stream without re-encoding (fast and lossless)
- `-map 0:v -map 1:a`: Explicitly map video from segments, audio from file
- `-movflags +faststart`: Optimize for web playback

##### Cleanup

```typescript
// Clean up temp files
try {
  if (fs.existsSync(inputListPath)) fs.unlinkSync(inputListPath);
  if (fs.existsSync(tempDir)) {
    fs.readdirSync(tempDir).forEach((file) => {
      fs.unlinkSync(path.join(tempDir, file));
    });
    fs.rmdirSync(tempDir);
  }
} catch (e) {
  logger.log(`[createVideo] Cleanup warning: ${e}`);
}
```

## Lessons Learned

### What Went Wrong

1. **Assumption Error:** Assumed FFmpeg concat demuxer would respect `duration` directives for static images
2. **Insufficient Testing:** Single-image tests passed, multi-image tests were not run early enough
3. **Silent Failures:** FFmpeg reported success but produced incorrect output
4. **Misleading Metadata:** File metadata showed correct duration, hiding the actual lack of content

### What Went Right

1. **Comprehensive Logging:** Added detailed logging that helped identify the exact point of failure
2. **Manual Testing:** Testing FFmpeg commands manually isolated the issue to the concat demuxer
3. **User Feedback:** Clear symptom reporting ("videos with 1 image work, 5 don't") helped narrow the scope
4. **Systematic Debugging:** Step-by-step analysis from logs → input files → manual commands → root cause

### Prevention for Future

1. **Always verify frame counts** in addition to duration
2. **Test with varying image counts** (1, 2, 5, 10 images)
3. **Use `ffprobe` to verify actual content**, not just metadata
4. **Document FFmpeg limitations** with specific input formats
5. **Add integration tests** for multi-image scenarios

## Glossary

| Term                     | Definition                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------- |
| **Concat Demuxer**       | FFmpeg component that reads multiple files and concatenates them into a single stream |
| **BMP**                  | Bitmap image format - stores image as uncompressed pixel data, typically 1 frame      |
| **Frame**                | A single image in a video sequence                                                    |
| **Duration**             | Length of time in seconds                                                             |
| **Framerate**            | Number of frames displayed per second (fps)                                           |
| **Segment**              | Individual video piece before concatenation                                           |
| **Two-Stage Conversion** | Process of converting source to intermediate format, then to final format             |
| **Stream Mapping**       | Explicitly telling FFmpeg which input streams to use in the output                    |
